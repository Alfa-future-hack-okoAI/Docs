# Ограничения и текущие решения

Состояние на 26.10.2026. Это не список уже реализованных следующих задач.

| Область | Текущее состояние | Что учитывать |
|---|---|---|
| ML polish | Не развёрнут на Cloud.ru | U_* в HTTP несовместим с UUID-проверками текущего BI |
| Компактная лента BI | Не реализована | feed включает полные article/card, display и highlight |
| Отдельный raw-ML summary endpoint BI | Нет | Снимок ML доступен как analysis.ml_summary |
| Обновление каждые 9 часов | Не реализовано | Нужен планировщик новых подготовок; GET только читает |
| Go Gateway/Insight production | Код существует, деплоя в текущем Compose нет | Не заявлять доступность серверных Insight URL |
| Некоторые BI imports | Отдельное задание заблокировано ValidationError | Диагностировать конкретный request; healthy/Account ready недостаточно |
| Периоды | ML поддерживает 24h/3d/7d/30d, BI 24h/1d…365d | BI читает свою историю; это не дополнительная генерация за год |
| Runtime state vs snapshot | Серверные данные устойчивы | Новый snapshot в образе не заменяет автоматически текущую SQLite |
| Прямой ML API | В серверном стенде без JWT | Не считать userId проверкой доступа |
| RoleView | Новая функция polish | В текущем dev её нет; будущий фоновый результат потребует ресинхронизации BI |
| Pin/hide/feedback | В polish есть ML-ручки; BI не проксирует | Не появятся в интерфейсе BI после одного обновления ML |
| Перерасчёт Insight | Меняет ML, не BI | До последующей синхронизации возможен stale reference 409 |
| История Insight | Хранится устойчиво, но не посылается в ML | История UI не равна многорепличному контексту модели |
| Новостные публикации | Исходные правки News не переиздаются | Не обещать автоматическое отслеживание исправлений источника |
| ML news-публикация | Нет отдельного transactional outbox | Есть окно между seen/done и отправкой processed |
| Данные компаний | Часть названий/ролей синтетическая, есть неизвестные поля | Сохранять data_warnings и null; не выдавать их за реальные реквизиты |

## Что уже работает

- Асинхронная команда Account с полным контекстом, включая ML-агрегаты.
- Новый рабочий адрес LLM в серверном runtime; ранее проверена новая генерация.
- Импорт корректных результатов в BI, лента, сводка, карточки и источники.
- Чтение последнего полного анализа по UUID компании с проверкой пользователя/роли.
- Автоматический выпуск четырёх сервисов через GHCR и Deployment после merge main.
- Реализация Go Gateway и Insight в отдельных репозиториях.

## До перехода на polish

1. Проверять соответствие UUID↔U_* по снимку Account, а не отключать identity-check.
2. Согласовать старые и новые card_id и их версии в БД/ссылках чата.
3. Проверить новые поля roleView/pinned, сюжетную дедупликацию и обновление снимков.
4. Прогнать Account → ML → BI → Insight с действующим JWT и чужим пользователем.
5. Выпустить отдельную совместимую версию адаптера BI/Insight до переключения ML.

Наличие функции в product/polish не означает, что она уже доступна в Cloud.ru BI.
